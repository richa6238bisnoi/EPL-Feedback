# Contributing to Giftogram Expense & Rewards Demo

Thank you for your interest in contributing! This repository is an **unofficial, community-built demo** inspired by Giftogram's public-facing rewards and gifting concepts. It is not an official Giftogram project.

## Contribution Guidelines

Please keep contributions focused, readable, accessible, and easy to maintain. Use clear naming, small reusable components, and descriptive commit messages. Do not add private, confidential, or trademark-sensitive material that you do not have permission to publish.

## How to Contribute

1. Fork the repository.
2. Create a new branch for your changes.
3. Install dependencies with `npm install`.
4. Follow the project's coding standards and existing component structure.
5. Test your changes with `npm test`.
6. Build the project with `npm run build` when appropriate.
7. Commit your changes and push the branch to your fork.
8. Open a pull request against the `main` branch.
9. Refer to this file when preparing your contribution.

## Reporting Issues

When reporting a bug, include:
- A clear description of the problem.
- Steps to reproduce it.
- Expected and actual behavior.
- Browser and operating-system details.
- Relevant console errors or screenshots, if available.

Please do not include passwords, access tokens, personal financial information, or other sensitive data.

## Suggesting Features

Feature requests should explain:
- The problem the feature would solve.
- The proposed behavior.
- Why it would be useful.
- Any accessibility, security, or usability considerations.

For features referring to Giftogram's real products or services, distinguish verified public information from proposed functionality in this demo.

## Code of Conduct

Be respectful, constructive, inclusive, and professional. Do not harass, discriminate against, or personally attack other contributors. Focus discussions on the code, documentation, and user experience.

## Review Process

Pull requests are reviewed for correctness, maintainability, accessibility, security, documentation, and consistency with the project. Reviewers may request changes before a contribution is merged. A passing test suite does not by itself guarantee acceptance; changes should also fit the project's purpose and structure.
